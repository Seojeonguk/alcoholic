# Google Play Console 등록

Play Console에서 앱을 처음 등록할 때 채우는 항목과 답을 정리했어요. 앱이 모으는 데이터나 기능이 바뀌면 이 문서와 [개인정보처리방침](privacy-policy.md)을 함께 고치고, 콘솔에도 똑같이 반영해요.

빌드와 업로드 명령은 README의 "빌드 · 배포"를 봐요.

## 출시 순서

1. Play Console에서 **앱 만들기**: 앱 이름 `Alcoholic`, 기본 언어 한국어, 앱(게임 아님), 무료.
2. 아래 [앱 콘텐츠](#앱-콘텐츠)와 [스토어 등록정보](#스토어-등록정보)를 채워요.
3. **내부 테스트**에 `production` 빌드 AAB를 직접 올리고, 내 기기에서 설치 · 동작을 확인해요(첫 업로드는 `eas submit`이 안 돼요).
4. **비공개 테스트**(closed testing)를 진행해요([비공개 테스트](#비공개-테스트)). 2023년 11월 13일 이후에 만든 **개인 개발자 계정**은 테스터 **12명 이상**이 **14일 연속**으로 참여해야 프로덕션 출시를 신청할 수 있어요([Google 안내](https://support.google.com/googleplay/android-developer/answer/14151465)). 내부 테스트는 이 조건에 들어가지 않아요. 조직 계정이거나 그 전에 만든 계정이면 건너뛰어요.
5. **프로덕션 액세스 신청** → 승인 후 테스트한 빌드를 **프로덕션**으로 승격해요.

## 앱 콘텐츠

Play Console **모니터링 및 개선 → 정책 및 프로그램 → 앱 콘텐츠**에서 채워요. 메뉴가 보이지 않으면 맨 위 검색창에 `앱 콘텐츠`를 쳐요. 이미 답한 항목은 **선언됨** 탭에 있어요.

### 개인정보처리방침

GitHub 저장소의 파일 주소(`github.com/.../blob/...`)가 아니라 GitHub Pages 주소를 넣어요. 앱 설정의 링크 · 데이터 보안의 계정 삭제 URL과 같은 주소예요.

```text
https://seojeonguk.github.io/alcoholic/privacy-policy
```

### 로그인 세부정보(앱 액세스)

예전 이름은 "앱 액세스"예요. **일부 기능에 로그인 등 특수한 액세스 권한이 필요함**을 고르고 **안내 추가**로 심사용 계정을 넣어요. 가입하지 않고도 기록을 쓸 수 있지만, 계정 백업 · 기기 기록 옮기기 · 탈퇴 같은 기능은 로그인해야 보이기 때문이에요. "모든 기능 사용 가능"으로 두면 심사자가 계정 삭제 기능을 확인하지 못해 거절될 수 있어요.

| 칸                     | 값                                                                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 이름                   | `심사용 계정`                                                                                                                                               |
| 사용자 이름 · 비밀번호 | 심사용 계정의 이메일 · 비밀번호                                                                                                                             |
| 추가 안내              | `첫 화면에서 "이메일로 시작하기"를 누르고 위 이메일과 비밀번호로 로그인해 주세요. 가입 없이 시작해도 기록을 쓸 수 있지만, 백업 · 탈퇴는 로그인해야 보여요.` |

- 개인 계정이 아니라 **심사 전용 이메일**(새 Gmail, 또는 Gmail의 `아이디+review@gmail.com` 별칭)로 가입해요. 심사자가 로그인해서 글을 보고 고칠 수 있기 때문이에요. 비밀번호도 다른 곳에서 쓰지 않는 것으로 정해요.
- 이메일 인증까지 마치고, 사진 · 주종 · 별점 · 태그 · 장소를 채운 글을 2~3개 써 둬요. 스토어 스크린샷도 이 계정으로 찍으면 가릴 개인정보가 없어요.
- **이 계정으로 탈퇴하지 않아요.** 지우면 심사가 거절돼요. 프로덕션 심사 때도 같은 계정을 써요.

### 광고

**아니요, 앱에 광고가 없습니다.**

### 광고 ID

**아니요**(광고 ID를 사용하지 않음). Android 13 이상을 대상으로 하는 앱은 이 선언을 하지 않으면 검토를 보낼 수 없어요. 광고 · Analytics SDK를 쓰지 않고, `node_modules`에도 `AD_ID` 권한을 넣는 라이브러리가 없어요. 올린 빌드의 **App Bundle 탐색기 → 세부정보 → 권한**에 `com.google.android.gms.permission.AD_ID`가 없는지 확인해요. 생기면 `app.config.js`의 `blockedPermissions`에 넣어요(새 빌드 필요).

### 콘텐츠 등급

카테고리는 **참고, 뉴스 또는 교육 이외의 모든 앱**(게임 아님)을 골라요. 질문에는 이렇게 답해요.

| 질문                                 | 답                                                      |
| ------------------------------------ | ------------------------------------------------------- |
| 폭력 · 성적 콘텐츠 · 욕설 · 도박     | 아니요                                                  |
| 규제 약물(알코올 · 담배 · 약물) 관련 | **예**: 알코올을 언급 · 묘사함(술 사진과 기록)          |
| 사용자 간 상호작용 · 콘텐츠 공유     | 아니요: 내가 쓴 글은 나만 볼 수 있어요                  |
| 사용자의 위치 공유                   | 아니요: 장소는 직접 적는 글이고 다른 사람에게 안 보여요 |
| 디지털 상품 구매                     | 아니요                                                  |

### 타겟층

**만 18세 이상**만 골라요. 술을 다루는 앱이라 아동 · 청소년을 대상으로 하지 않아요. 콘솔에서 고를 수 있는 가장 높은 구간이 18세 이상이라, 한국 기준인 만 19세는 개인정보처리방침 9번과 스토어 설명의 안내 문구로 맞춰요.

### 데이터 보안

[Firebase의 데이터 수집 안내](https://firebase.google.com/docs/android/play-data-disclosure)와 앱 코드를 기준으로 정리했어요. 앱은 Analytics · 광고 SDK를 쓰지 않아요. 크래시는 Firebase Crashlytics(`@react-native-firebase/crashlytics`)로 모아요. 공지 알림은 Firebase Cloud Messaging(`@react-native-firebase/messaging`)으로 보내요([공지 알림 보내기](notifications.md)). 업데이트는 Expo의 EAS Update(`expo-updates`)로 받아요.

**수집하는 데이터** — 모두 **공유하지 않음**(Google(Firebase) · Expo(EAS Update)는 처리 위탁이라 공유에 해당하지 않아요), **임시 처리 아님**이에요.

- 사진은 기기에 저장된 사진 전체가 아니라 사용자가 고른 사진만 올라가요. 회원 글은 갤러리용 썸네일(대표 사진을 줄인 사진)을 한 장 더 저장해요(같은 "사진" 유형).
- **사진으로 술 알아보기**(#380 · #381)는 회원이 버튼을 누를 때 첫 번째 사진(줄인 사본)을 Cloud Functions를 거쳐 Anthropic(Claude API)에 보내요. 운영자를 대신해 처리하는 서비스 제공업체라 **공유에 해당하지 않고**, 같은 "사진" 유형(목적: 앱 기능)에 들어가요. 사진은 게시글로도 저장되므로 "임시 처리"는 고르지 않아요. 하루 사용 횟수(계정 ID · 날짜 · 횟수)는 Firestore에 두고 이틀 뒤 TTL로 지워요(같은 "사용자 ID" 유형).
- 기록 내보내기 · 공유는 사용자가 고른 앱으로 기기에서 바로 보내고 서버를 거치지 않아서 수집 · 공유에 해당하지 않아요.
- IP 주소를 어느 유형으로 볼지는 Google이 따로 정해 두지 않았어요. 보수적으로 "기기 또는 기타 ID"에 넣었어요.
- FCM 등록 토큰은 공지 알림을 켠 사용자에게만 만들어지지만, 같은 "기기 또는 기타 ID" 유형에 이미 필수 항목(Firebase 설치 ID 등)이 있어서 유형 전체를 필수로 둬요. 공지 알림은 Google이 "앱 · 개발자 소식 보내기"로 정의한 **개발자 커뮤니케이션**에 해당해서 이 목적도 체크해요. 운영자는 토큰을 저장하지 않고 토픽으로만 보내요.
- 미리보기에서 "서드 파티와 공유되는 데이터 없음", "전송 중 데이터 암호화", "데이터 삭제를 요청할 수 있음"이 보이고, 위치 · 앱 상호작용 · 광고 또는 마케팅 · 맞춤설정이 없는지 확인하고 제출해요.
