# 앱 디자인 개편 설계

- 작성일: 2026-10-26
- 대상 버전: v1.0.0(출시 전)
- 관련 이슈: #256(사진 줄이기)을 v1.0.0으로 당겨 함께 진행

## 왜 하나요

지금 앱은 크림색 배경에 파스텔 색(하늘 · 연분홍 · 회청 · 남색)이 여러 개 섞여 있고, 화면마다 버튼 · 입력 칸 모양이 제각각이에요. 사용자는 **토스처럼 깔끔하고 빠릿빠릿한 앱**을 원해요. 특히 좋다고 한 건 두 가지예요.

1. **깔끔한 느낌**: 흰 배경, 색은 강조할 곳에만, 큰 글씨와 넓은 여백
2. **빠릿빠릿함**: 버튼을 누르면 바로 반응하고, 기다리는 시간이 짧거나 덜 답답함. 사용자가 든 예는 "사진이 있는 글을 저장할 때 스피너가 오래 돈다"예요.

## 목표

- 앱 전체 화면을 하나의 디자인 규칙(색 · 글씨 · 모양 · 간격)으로 통일해요.
- 사진이 가장 화려한 요소가 되도록 화면은 조용하게 둬요.
- 글 저장 대기를 실제로 줄이고(사진 줄이기), 기다리는 동안 진행 상황을 보여 줘요.

## 하지 않는 것

- 다크 모드
- 새 기능 추가(검색, 통계 등). 화면에 보이는 정보와 할 수 있는 일은 지금과 같아요.
- 데이터 구조 · 보안 규칙 변경
- 저장을 누르고 바로 돌아가는 "뒤에서 올리기"(실패 처리가 복잡해서 출시 전에는 넣지 않음)
- 앱 아이콘 다시 그리기(#241 아이콘 유지)

## 실패로 보는 것

- 토스를 그대로 베낀 것처럼 보이는 것(토스 파랑 `#3182f6`을 쓰지 않는 이유)
- 예쁘지만 느려지는 것: 무거운 애니메이션 라이브러리, 큰 커스텀 폰트로 앱이 무거워지는 것
- 기존 동작이 깨지는 것: 로그인 · 가입 · 글 쓰기 · 수정 · 삭제 · 탈퇴 흐름과 #246 · #249 · #268에서 고친 동작은 그대로여야 해요.

## 제약

- Expo SDK 58 · React Native 0.88 · React 19 · React Navigation 7, JavaScript(타입스크립트 아님)
- 패키지는 `npx expo install`로 추가해요. 네이티브 설정을 바꾸는 패키지는 EAS 빌드가 필요해요.
- 사진 · 오디오 권한을 새로 요청하지 않아요(CLAUDE.md).
- 사용자에게 보이는 문구는 한국어예요.
- 이 환경에서는 기기에서 실행해 볼 수 없어서, 확인은 PR 체크리스트로 사용자가 해요.

## 디자인 규칙 (사용자와 정한 것)

브레인스토밍에서 시안 세 가지 중 **A안 "토스식 화이트"**를 골랐어요.

### 색

`constants/theme.js`의 `COLORS`를 아래로 바꿔요. 지금 쓰는 파스텔 색(`BUTTON_COLOR`, `FIRST_SUB_COLOR`, `BOTTOM_TAB_*` 등)은 모두 이 토큰으로 옮기고 없애요.

| 토큰(제안 이름) | 값        | 쓰는 곳                                         |
| --------------- | --------- | ----------------------------------------------- |
| `BACKGROUND`    | `#FFFFFF` | 모든 화면 배경                                  |
| `ACCENT`        | `#2E699A` | 주요 버튼, 선택 상태, 입력 중인 칸 테두리, 링크 |
| `ACCENT_SOFT`   | `#E8F0F7` | 보조 버튼 배경, 아이콘 배경                     |
| `TEXT`          | `#191F28` | 제목 · 본문                                     |
| `TEXT_SUB`      | `#8B95A1` | 보조 글씨, 라벨, 목록의 값                      |
| `FILL`          | `#F2F4F6` | 입력 칸 배경, 사진 추가 칸, 태그 칩 배경        |
| `LINE`          | `#F2F4F6` | 목록 구분선, 탭 바 위 선                        |
| `DANGER`        | `#E5484D` | 삭제 · 탈퇴 같은 되돌릴 수 없는 행동, 에러 글씨 |

- 강조색은 **남색 `#2E699A` 하나**예요. 사용자가 "추천대로"라고 해서 정했어요. 흰 글씨 대비가 약 5.9:1로 접근성 기준(4.5:1)을 넘고, 토스와 구분되며, 원래 팔레트를 이어 가요.
- 맥주 느낌의 따뜻한 색은 화면 UI에 쓰지 않아요. 앱 아이콘과 사진이 맡아요.

### 글씨

| 역할                     | 크기 / 굵기                   |
| ------------------------ | ----------------------------- |
| 화면 제목                | 24 / 800, 글자 사이 약간 좁게 |
| 큰 문구(첫 화면)         | 26 / 800, 두 줄               |
| 섹션 제목(월, 설정 묶음) | 13 / 700, `TEXT_SUB`          |
| 본문 · 목록              | 15 / 400~500                  |
| 보조 · 메타              | 13 / 400, `TEXT_SUB`          |
| 버튼                     | 16 / 700                      |

### 모양 · 간격

- 화면 좌우 여백 20, 둥근 모서리는 사진 12, 입력 칸 12, 버튼 14
- 테두리 선은 거의 쓰지 않고 면(`FILL`)과 여백으로 구분해요. 입력 중인 칸만 `ACCENT` 2px 테두리를 둬요.
- **주요 버튼은 화면 아래쪽에 고정**하고 좌우를 꽉 채워요(좌우 16, 아래는 안전 영역 + 12). 키보드가 올라오면 키보드 위로 올라가요.

### 반응 · 전환 (빠릿빠릿함)

- 버튼 · 사진 칸 · 목록 줄을 누르면 **살짝 작아졌다(약 0.97배) 돌아와요.** React Native 기본 `Animated`나 `Pressable`로 만들고 새 애니메이션 라이브러리는 넣지 않아요.
- 화면 전환은 지금 쓰는 native stack 기본 전환을 그대로 써요.
- 화면 전체를 덮는 스피너는 쓰지 않아요. 기다릴 때는 **누른 버튼 안에서** 상태를 보여 줘요(예: "사진 올리는 중 2/3", "삭제하는 중…"). 버튼은 그동안 눌리지 않아요.
- 처음 데이터를 불러오는 화면(갤러리 · 상세)은 스피너 대신 회색 자리 표시(스켈레톤)를 보여 줘요.

## 화면별 설계 (사용자와 정한 것)

브라우저 시안으로 보여 주고 확인받은 모양이에요.

### 공통 헤더 · 탭

- 뒤로 가기가 있는 화면은 왼쪽 위 `‹`(또는 글 쓰기는 `✕`), 가운데 작은 제목(필요할 때만)이에요.
- 하단 탭은 흰 배경, 위쪽 옅은 선, 아이콘 + 한국어 라벨 **"기록" · "설정"**이에요. 선택된 탭은 `TEXT`, 나머지는 회색이에요. 지금 라벨은 `Gallery` · `Settings`(내비게이션 이름)라서 바꿔요.

### 첫 화면 (`MainPage`)

- 위쪽 여백 → 둥근 사각형(`ACCENT_SOFT`) 안의 앱 아이콘 → 큰 문구 "오늘 마신 술,\n사진으로 남겨요" → 보조 문구 "나만 보는 술 기록장"
- 아래 고정: 주요 버튼 "이메일로 시작하기"(로그인으로), 그 아래 글씨 버튼 "처음이에요 · 회원가입"
- 지금 쓰는 `mainPageImg.png`는 쓰지 않아요.

### 로그인 · 회원가입 · 비밀번호 찾기 · 탈퇴 (같은 틀)

- 왼쪽 위 `‹`, 큰 제목(예: "이메일로 로그인", "이메일로 회원가입", "비밀번호를 잊으셨나요?", "탈퇴하기")
- 입력 칸: `FILL` 면, 둥근 12, 라벨은 칸 위 작은 회색 글씨, 입력 중이면 `ACCENT` 테두리, 에러는 칸 아래 `DANGER` 작은 글씨
- 비밀번호 칸은 #268의 `PasswordInput`(눈 아이콘)을 새 모양으로 바꿔 써요.
- 주요 버튼은 아래 고정. 로그인 화면에는 "비밀번호를 잊으셨나요?" 글씨 링크를 입력 칸 아래에 둬요. 로그인 화면의 "회원가입" 버튼은 첫 화면에 있으므로 빼요.
- 탈퇴 화면 버튼은 `DANGER` 색이에요.

### 갤러리 (`Gallery`)

- 큰 제목 "내 기록", 오른쪽에 `ACCENT` 둥근 사각형 + 버튼
- 글을 **마신 날짜(`day`)순**(최근 날짜가 위)으로 정렬하고, 같은 날짜 안에서는 최근에 쓴 글(`createdAt`)이 앞에 와요. 사용자가 정했어요.
  - 지금 `getPosts`는 `createdAt`으로만 정렬하고 `presentivePhoto` · `docId`만 돌려줘요. `day`도 받아서 정렬해야 해요. Firestore 쿼리는 지금처럼 `writer` + `createdAt`으로 두고 앱에서 다시 정렬하면 새 색인이 필요 없어요(제 결정, 만드는 사람이 바꿔도 돼요).
  - 이렇게 하면 지난달 술을 오늘 기록해도 그 달 묶음에 들어가고, 날짜를 바꾸지 않고 수정하면 순서가 그대로예요(#246).
- **마신 날짜의 월별로 묶어** "10월"처럼 섹션 제목을 달아요. 올해가 아니면 "2025년 12월"처럼 연도를 붙여요.
- 섹션 안은 3열 정사각형 사진, 간격 6, 둥근 12. #268의 `expo-image` 캐시 · `cover`는 그대로 써요.
- 빈 상태: 가운데 안내 "아직 남긴 기록이 없어요." + 보조 문구 + "첫 기록 남기기" 버튼(글 쓰기로)

### 글 쓰기 · 수정 (`GalleryForm`)

- 위: `✕`(닫기), 가운데 "새 기록" 또는 "기록 수정"
- 순서: 사진 줄(맨 앞 `FILL` + 칸, 그 뒤 고른 사진 미리보기, 가로 스크롤, 각 사진에 작은 삭제 버튼) → 제목 칸(크게) → 날짜 · 장소 · 태그 목록 줄 → 내용 칸(여러 줄)
- 날짜 줄은 오른쪽에 "2026. 10. 26 ›", 누르면 지금처럼 날짜 선택기. 장소 줄은 누르면 입력할 수 있어요.
- 태그는 `FILL` 칩(`#맥주`)으로 보여 주고 "+ 추가"로 입력해요. 칩을 누르면 지워요(지금 동작 유지).
- 아래 고정 "저장하기" 버튼. 저장 중에는 버튼 글씨가 **"사진 올리는 중 n/전체"** → "저장하는 중…"으로 바뀌고 눌리지 않아요.

### 상세 (`Details`)

- 사진 캐러셀이 화면 위를 꽉 채우고(가로 꽉, 높이는 화면 너비 정도), 그 위에 흰 `‹`와 `⋯`, 아래쪽 가운데 점 표시(현재 사진은 길쭉한 점)
- 그 아래: 제목(크게) → "2026. 10. 26 · 장소" 메타 한 줄 → 내용 → 태그 칩
- `⋯`를 누르면 "수정" · "삭제" 선택지가 나와요. 삭제는 지금처럼 확인 창을 거쳐요(#249). 지금 내용 아래의 "글 삭제" 글씨 버튼과 헤더 연필 아이콘은 없애요.

### 설정 (`Settings`)

- 큰 제목 "설정"
- 묶음 "계정": 이메일(값만), 로그아웃(›)
- 묶음 "앱 정보": 버전(값), 개인정보처리방침(›)
- 맨 아래 작은 회색 글씨 "탈퇴하기"(탈퇴 화면으로)
- 지금의 큰 사용자 아이콘은 없애요.

### 개인정보처리방침 안내 문구

- 4번 "게시글만 지우기"의 "글을 열고 아래쪽의 **글 삭제**를 누르면"을 새 위치("글을 열고 오른쪽 위 **⋯ → 삭제**를 누르면")로 고쳐요. 상세 화면을 바꾸는 PR에 함께 넣어요(제 결정).
- 방침은 앱에서 GitHub `master` 파일로 바로 연결돼서 머지하면 공개돼요. 아직 출시 전이라 해당 기능 PR에 함께 넣어도 돼요(제 결정).

## 사진 줄이기 (#256, 사용자와 정한 것)

- 올리기 전에 `expo-image-manipulator`로 **긴 변 최대 1600px, JPEG 품질 0.8**로 줄여요. 이미 더 작은 사진은 키우지 않아요.
- 줄인 사진에는 촬영 위치 같은 메타데이터가 남지 않아요. 개인정보처리방침 1번의 "사진 파일에 들어 있는 촬영 정보(메타데이터)가 함께 저장될 수 있어요"를 **"앞으로 올리는 사진은 크기를 줄여 저장하며, 이때 촬영 정보(메타데이터)는 빠져요. 이전에 올린 사진에는 남아 있을 수 있어요."**처럼 고쳐요(제 결정: 이미 올라간 사진이 있어서 단정하지 않음).
- 저장 버튼에 진행 상황(`n/전체`)을 보여 줘요. 사진은 지금처럼 동시에 올리고, 하나가 끝날 때마다 숫자가 올라가요.
- 이미 올라간 사진(수정할 때의 기존 사진)은 다시 줄이거나 올리지 않아요.
