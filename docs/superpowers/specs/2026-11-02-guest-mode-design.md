# 회원가입 없이 쓰기 설계

- 작성일: 2026-11-02
- 대상 버전: v1.0.0
- 관련 이슈: #201

## 왜 하나요

지금은 이메일로 가입하고 인증 메일까지 확인해야 첫 기록을 남길 수 있어요. **기기 하나에서 가볍게 기록만 하려는 사람**에게는 이 과정이 첫 기록을 막는 벽이에요.

그래서 가입 없이 바로 기록할 수 있게 해요. 나중에 기기를 바꾸거나 백업하고 싶어지면 그때 가입하고, 그동안 쓴 기록을 그대로 계정으로 옮겨요.

## 목표

- 첫 화면에서 "가입 없이 시작하기"를 누르면 바로 기록을 시작할 수 있어요.
- 비회원의 기록 · 사진은 **기기 안에만** 저장하고 서버(Firebase)로 보내지 않아요.
- 인증을 마친 계정으로 로그인하면 기기의 비회원 기록을 그 계정으로 옮겨요. 새로 가입한 계정이든 원래 있던 계정이든 같아요.
- 비회원도 회원과 같은 기능(사진 여러 장, 제목 · 날짜 · 장소 · 태그 · 내용, 갤러리 필터, 수정 · 삭제)을 써요.

## 하지 않는 것

- Firebase 익명 로그인. 가입 전에는 기록이 기기 밖으로 나가지 않아야 해서 쓰지 않아요.
- 비회원 기록의 파일 내보내기 · 가져오기, 클라우드 백업(Google Drive 등)
- 회원의 기록을 기기에 오프라인으로 저장하기(지금처럼 Firestore 캐시만 씀)
- 기기 하나에서 비회원 기록과 회원 기록을 동시에 보기
- 지금 회원의 흐름(가입 · 인증 · 로그인 · 비밀번호 찾기 · 탈퇴) 바꾸기
- 보안 규칙 · Firestore 데이터 구조 바꾸기. 옮긴 기록은 회원이 쓴 기록과 똑같은 모양으로 저장해요.

## 실패로 보는 것

- 옮기다가 기록이나 사진이 **사라지는** 것. 앱이 꺼지거나 인터넷이 끊겨도 안 돼요.
- 다시 시도했을 때 같은 기록이 **두 번** 올라가는 것
- 가입 전에 비회원 기록이 서버로 나가는 것
- 비회원이 기록을 쓰다가 가입을 권하는 안내에 계속 시달리는 것

## 제약

- 지금 데이터는 **이메일**이 기준이에요. `users/{email}` 문서, 게시글의 `writer`, 보안 규칙이 모두 이메일을 보고, 게시글을 쓰려면 이메일 인증(`email_verified`)이 필요해요. 그래서 기록은 **인증을 마친 계정으로 로그인한 뒤에만** 옮길 수 있어요.
- Storage 규칙은 같은 경로의 파일을 덮어쓰지 못하게 막아요(`resource == null`일 때만 만들기 허용).
- 사진 선택기가 주는 파일 · 줄인 사진은 캐시 폴더에 있어서 시스템이 지울 수 있어요. 비회원 사진은 앱이 지우지 않는 폴더로 복사해 둬야 해요.
- 새 네이티브 패키지가 들어가면 EAS Update로 배포할 수 없고 새 빌드가 필요해요(CLAUDE.md).
- 사진 · 오디오 권한을 새로 추가하지 않아요(CLAUDE.md).

## 사용자와 정한 것

### 누구를 위한 기능인가요

- 기기 하나에서 가볍게 기록만 하려는 사람이에요.
- 기기를 바꾸거나 백업하고 싶으면 가입한 뒤 서버에 저장해요.

### 저장 위치

- 가입 전에는 기록 · 사진을 **기기에만** 저장해요.
- 가입(인증 완료 후 로그인)하면 기기의 기록 · 사진을 서버로 옮기고, 다 옮긴 것은 기기에서 지워요.

### 이미 있는 계정으로 로그인할 때

- 비회원으로 쓰던 사람이 원래 있던 계정으로 로그인해도 기기의 기록을 **그 계정으로 합쳐요.** 계정에 있던 기록은 그대로 두고 더해요.

### 처음 들어오는 흐름

- 첫 화면에 **"가입 없이 시작하기"** 버튼을 둬요. 누르면 바로 갤러리로 가요.
- 비회원으로 시작한 사람이 앱을 다시 열면 첫 화면을 건너뛰고 갤러리로 가요.
- 회원이 로그아웃하면 다시 첫 화면이 나와요.

## 제가 정한 것 (사용자가 따로 말하지 않은 부분)

### 버튼 위치

- 사용자는 "로그인 화면"이라고 했지만, 앱을 열면 처음 보이는 화면은 `MainPage`(첫 화면: "이메일로 시작하기" · "처음이에요 · 회원가입")예요. 그래서 버튼은 **`MainPage`**에 둬요.
- 순서는 "이메일로 시작하기"(주 버튼) → "처음이에요 · 회원가입"(글자 버튼) → "가입 없이 시작하기"(글자 버튼)예요.

### 앱 상태 세 가지

| 상태 | 언제 | 처음 보이는 화면 | 기록을 읽고 쓰는 곳 |
|---|---|---|---|
| 회원 | 인증을 마친 계정으로 로그인돼 있음 | 갤러리 | Firestore · Storage(지금과 같음) |
| 비회원 | "가입 없이 시작하기"를 누른 적이 있고, 인증된 로그인이 없음 | 갤러리 | 기기 |
| 처음 | 둘 다 아님 | 첫 화면(`MainPage`) | 없음 |

- 비회원 여부는 기기에 저장한 표시(AsyncStorage 키)로 기억해요.
- **인증된 로그인이 있으면 항상 회원 상태**가 우선이에요. 가입만 하고 인증을 안 한 계정이 로그인돼 있어도 비회원 표시가 있으면 비회원 상태예요(지금도 인증 안 된 계정은 갤러리로 못 가요).
- 인증된 계정으로 로그인하면 비회원 표시를 지워요. 그래서 로그아웃하면 첫 화면으로 가요.

### 비회원일 때 화면

- **갤러리 · 작성 · 상세**: 회원과 똑같이 보여요. 비회원이라는 표시나 가입 권유를 넣지 않아요.
- **설정**
  - "계정" 칸: 이메일 · 로그아웃 대신 **"가입하고 기록 백업하기"** 한 줄을 둬요. 누르면 첫 화면으로 가서(스택에 쌓음, 뒤로 가면 설정) 로그인 · 회원가입을 할 수 있어요.
  - 그 아래에 작은 글씨로 "기록은 이 기기에만 있어요. 앱을 지우면 기록도 사라져요."를 적어요.
  - 맨 아래 "탈퇴하기" 자리에 **"기기의 기록 모두 지우기"**를 둬요. 확인 창("기기에 저장된 기록과 사진이 모두 삭제되며 되돌릴 수 없어요.")을 거친 뒤 지워요. 지운 뒤에도 비회원 상태는 그대로예요.
- 비회원 상태에서 첫 화면으로 간 뒤 로그인하지 않고 뒤로 가면 그대로 비회원이에요.

### 기기에 저장하는 방식

- 사진은 앱 문서 폴더(예: `documentDirectory/guest/photos/`)에 **복사**해 둬요. 저장할 때 업로드용으로 줄인 사진(`resizeForUpload` 결과)을 복사하면 회원과 같은 크기가 돼요.
- 글은 회원 글과 같은 필드(`title`, `day`, `photos`, `content`, `location`, `tags`, `createdAt`)를 기기에 저장해요. `photos`에는 기기 사진 경로가 들어가요. `writer`는 저장하지 않아요(옮길 때 채움).
- 글 ID는 기기에서 만든 무작위 ID(`react-native-uuid`)예요. **옮길 때 Firestore 문서 ID로 그대로 써요**(아래 "옮기기").
- 글 길이 · 개수 상한(`constants/postLimits.js`)은 비회원에게도 똑같이 적용해요. 옮길 때 보안 규칙에서 거절되지 않게 하려는 거예요.
- 화면은 지금 `services`의 함수(`getPosts`, `getPost`, `createNewPost`, `updateDocForId`, `deletePost`)를 불러요. 비회원용으로 같은 일을 하는 함수를 만들고, 화면은 상태에 따라 한쪽을 골라 써요. 반환 모양(예: `getPosts`의 `{ docId, presentivePhoto, day, tags, createdAt }`)은 같게 맞춰요.

### 옮기기

**언제**
- 회원 상태로 들어갈 때마다(앱을 켤 때 인증된 로그인이 있거나, 로그인 화면에서 인증된 계정으로 로그인했을 때) 기기에 비회원 기록이 남아 있으면 옮겨요.
- 그래서 중간에 실패해도 다음에 앱을 켜거나 로그인하면 남은 것부터 다시 옮겨요.

**어떻게 (기록 하나씩)**
1. 사진을 `posts/{uid}/{사진 ID}`로 올려요. 사진 ID는 기기 파일 이름에서 가져와서, 다시 시도해도 같은 경로가 돼요. 이미 올라가 있으면(규칙상 덮어쓸 수 없음) 올리지 않고 다운로드 URL만 받아요.
2. `posts/{기기 글 ID}`에 글을 써요(`writer`는 로그인한 이메일, `createdAt`은 기기에 저장한 시각). 문서 ID가 정해져 있어서 다시 시도해도 같은 문서에 써지고 두 번 생기지 않아요.
3. `users/{email}`의 `posts`에 글 ID를 더해요(`arrayUnion`이라 두 번 더해도 하나).
4. 위 세 단계가 모두 끝난 기록만 기기에서 글과 사진을 지워요.

- 가입 때 `users/{email}` 문서가 만들어지지 않은 계정(예전 실패 등)이면 먼저 만들어요.
- 기록 하나가 실패하면 그 기록은 기기에 남기고 다음 기록으로 넘어가요. 끝나면 결과를 알려요.

**옮기다 남은 기록의 주인 (사용자와 정한 것)**
- 옮기기를 시작할 때 아직 주인이 없는 기기 기록 모두에 **그 계정의 uid를 적어 둬요.** 이때부터 이 기록은 그 계정의 것이에요.
- 주인이 적힌 기록은 **같은 계정으로 로그인했을 때만** 이어서 옮겨요. 다른 계정으로 로그인하면 건드리지 않아요. 그래서 이미 A의 글로 써진 문서를 B가 다시 쓰려다 규칙에 막히는 일이 없고, 공용 기기에서 A의 기록이 B에게 넘어가지 않아요.
- 비회원 화면(갤러리 · 상세 · "기기의 기록 모두 지우기")은 **주인이 없는 기록만** 보여 주고 다뤄요. 남은 A의 기록은 다음 비회원에게 보이지 않아요.
- A가 다시 로그인하지 않으면 남은 기록은 보이지 않는 채로 기기에 남아요(앱을 지우면 함께 지워짐). 기록 하나씩 옮기고 실패하면 다음 로그인 때 다시 시도하므로 드문 경우로 보고 받아들여요.
- 상태 판단 · 옮길 기록 고르기(주인 없음 또는 주인 == 지금 uid)는 `lib/`의 순수 함수로 두고 경우별로 테스트해요.

**보이는 것**
- 옮기는 동안 갤러리 위쪽(지금 다시 불러오기 표시 자리)에 "기기의 기록 옮기는 중 3/10"처럼 보여 줘요. 화면을 막지 않아요.
- 끝나면 알림: "기기에 있던 기록 10개를 계정으로 옮겼어요." / 일부 실패: "기록 2개를 옮기지 못했어요. 다음에 다시 시도할게요."
- 다 옮긴 뒤 갤러리를 다시 불러와서 원래 계정 기록과 함께 마신 날짜순으로 보여 줘요.

### 개인정보처리방침

- "가입하지 않고 쓰면 기록 · 사진은 기기에만 저장되고 수집하지 않아요. 가입하면 그때부터 서버에 저장돼요."를 더해요.
- 86줄의 "국외 이전을 원하지 않으면 회원가입을 하지 않거나 … 이 경우 앱을 이용할 수 없어요."를 "가입하지 않고 기기에만 저장해 쓸 수 있어요"로 고쳐요.
- Crashlytics · Expo(업데이트 확인) · App Check는 비회원에게도 그대로 동작해요. 기록 내용은 들어가지 않아요.
- 이미 공개한 방침이면 11번에 따라 시행일을 바꾸고 알려야 해요(사용자가 확인).

### 버전

- v1.0.0 출시 전에 넣는 새 기능이에요. 기기 저장에 네이티브 패키지(`expo-file-system`, `npx expo install`)가 들어가면 새 빌드가 필요해요. PR 본문에 적어요.

## 만드는 사람에게 맡기는 것

- 기기에 글을 저장하는 형식(문서 폴더의 JSON 파일 하나 또는 AsyncStorage). 글 수백 개, 내용 2,000자까지 버텨야 하고, 쓰다가 앱이 꺼져도 파일이 깨지지 않아야 해요(임시 파일에 쓴 뒤 바꾸기 등).
- 상태(회원 · 비회원 · 처음)를 화면에 전하는 방법(Redux slice, Context, 작은 모듈)
- 함수 · 파일 이름, 비회원용 함수를 `services/` 안에 둘지 따로 둘지
- 옮기기를 실행하는 위치(갤러리 화면, `MainPage`, 별도 hook)
- 옮길 때 사진을 동시에 몇 장 올릴지

## 확인 방법

- 순수 함수(상태 판단, 기기 글 → 갤러리 목록 변환, 옮길 데이터 만들기)는 `lib/`에 두고 `node --test` 단위 테스트를 써요.
- 보안 규칙을 바꾸지 않으므로 규칙 테스트는 그대로 통과해야 해요. 옮긴 글 모양(정해진 문서 ID, `writer`, `createdAt`)이 규칙을 통과하는지 테스트를 하나 더해요.
- `npm run lint`, `npm run test:unit`, `npx expo-doctor`, `npx expo export --platform android`
- 기기 확인(사용자): 비회원으로 시작 → 사진 있는 기록 쓰기 · 수정 · 삭제 → 앱 껐다 켜기(바로 갤러리) → 새로 가입 · 인증 · 로그인(기록이 옮겨짐, 기기에서 사라짐) → 로그아웃(첫 화면) / 비회원 기록이 있는 채로 기존 계정 로그인(합쳐짐) / 옮기는 중 비행기 모드(다음 로그인 때 남은 것만 옮겨짐, 중복 없음) / 옮기다 남은 채로 로그아웃 → 다른 계정 로그인(옮겨지지 않음) · 가입 없이 시작하기(보이지 않음) → 처음 계정으로 다시 로그인(이어서 옮겨짐) / 기기의 기록 모두 지우기
